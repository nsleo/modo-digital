# Manutencao da documentacao

## Objetivo

Garantir que qualquer pessoa consiga entender e operar o projeto sem depender de contexto oral ou de um chat anterior.

## Quando a documentacao deve ser atualizada

Atualize a docs sempre que houver mudanca em:

- scripts
- comandos principais
- fluxo de build
- fluxo de publicacao
- estrutura de pastas
- componentes-base
- padroes de design system
- regras operacionais
- hospedagem ou deploy

## Ordem de revisao

1. `README.md`
2. `docs/arquitetura.md`
3. guia operacional afetado
4. este arquivo, se a regra de manutencao mudar

## Regra pratica

Se uma alteracao faz alguem perguntar "como funciona agora?", essa alteracao quase sempre exige ajuste de documentacao.

## Escopo da documentacao

A documentacao deve ser:

- direta
- curta
- suficiente para operacao
- sem floreio
- orientada a quem nao tem contexto previo
